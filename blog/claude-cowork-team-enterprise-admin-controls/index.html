How does Claude Cowork work on Team and Enterprise plans, and what can admins control?

By Manthan Bhendkar · 6 min read · Published 19 November 2026 · Last updated 19 November 2026

Disclosure: Asendify publishes this page and makes some of the options mentioned here; ours are named as ours. Every option is described from its own official page, and prices and features can change, so check before you buy.

On Team and Enterprise plans, Cowork is switched on by default and owners decide how far it can go: whether tasks run in the cloud, whether members may use "Automatically approve" mode, whether connector tools that write data need approval each time, which plugins are installed, what network access sessions get and whether the browser is available. Enterprise adds per-group controls and audit access through the Compliance API.

Key takeaways

  • Anthropic's help centre says Cowork is on by default for Team and Enterprise; Owners can turn it off in Organization settings > Cowork. In HIPAA-enabled organisations it starts off.
  • Running Cowork in the cloud is on by default for Team but off by default for Enterprise, where owners grant it to groups through custom roles.
  • "Always allow" for connector tools is off by default, so members approve write-capable connector tools per task.
  • Network egress rules do not cover web fetch, web search or MCP connectors, including Claude in Chrome.
  • Cowork left research preview and became generally available on 10 April 2026, adding role-based access, spend limits and analytics for organisations.

Where it stands

TechRadar reported on 10 April 2026 that Anthropic had made Cowork generally available after its research preview, with role-based access controls, spend limits and usage controls, analytics, and integrations and plugins for organisations. eWeek's report the same day added expanded OpenTelemetry support and per-tool connector limits, such as blocking write actions.

The detail of what admins can set lives in Anthropic's help article, Use Claude Cowork on Team and Enterprise plans.

Connectors: the setting that matters most

The help article explains that when "Always allow" for connector tools is off, members must approve write-capable tools for each task. Read-only tools are only exempt if the connector marks them as read-only, and most custom connectors do not, so their tools stay gated. On Enterprise, custom role grants cannot override this toggle. For most businesses, leaving it off is the safer default until you know which tools you trust.

Plugins

There is no separate plugin switch for Cowork; plugins follow the Cowork toggle. Owners can build plugin marketplaces with four statuses: installed by default, available to install, required, or not available. Enterprise admins can set these per group.

Network and browser

Network egress is set under Organization settings > Capabilities > Code execution, and Anthropic advises reviewing it before enabling Cowork. Changes only apply to new sessions. Importantly, egress rules "don't cover web fetch, web search, or MCPs (including Claude in Chrome)", so restricting egress is not the same as restricting what Claude can read from the web.

Both the built-in browser and Claude in Chrome use a blocklist for high-risk sites and a safety check on each action, and browser traffic appears to come from the user's device.

Audit, monitoring and data

  • Compliance API captures Cowork sessions from Claude, Claude Desktop and Claude Mobile, returning the most recent 30 days (or less if your retention period is shorter).
  • OpenTelemetry streams events such as tool calls, file access and approval decisions to your monitoring tools. Anthropic says it does not replace compliance audit logging.
  • EDR (beta on macOS and Windows) lets admins run their endpoint sensor inside the local virtual machine; it does not cover cloud sessions.
  • Local sessions are stored on users' computers, are not subject to Anthropic's standard retention, and cannot yet be deleted centrally.
  • HIPAA: with the HIPAA configuration applied, the BAA covers Cowork in Claude Desktop; cloud sessions and the built-in browser are unavailable under it.

A sensible starting policy

  1. Leave "Always allow" for connector tools off.
  2. Decide whether members need "Automatically approve" at all in the first month.
  3. Review network egress before rollout, remembering it does not cover web fetch, search or MCPs.
  4. Publish a small set of plugins as "available" and make only essential ones "required".
  5. Turn on OpenTelemetry or Compliance API access before broad rollout, not after an incident.
  6. Tell staff the help centre's safety advice: avoid giving Claude sensitive files it does not need, watch what it does and report anything suspicious. Anthropic calls prompt injection risk "non-zero".

Worked example

Example: a 25-person accounting firm on the Team plan wants to pilot Cowork with five staff.

  • Week 0: the owner keeps Cowork on but turns off "Allow 'Automatically approve' mode" so every action needs approval during the pilot. Connector "Always allow" stays off.
  • Plugins: one internal plugin with the firm's month-end checklist is set to "available to install"; nothing is required yet.
  • Egress: reviewed and limited to the services the pilot needs, with a note that web search is a separate switch under Capabilities, which they leave on.
  • Week 4 review: the five staff report which tasks worked. The owner allows "Automatically approve" for the two tasks that only read and summarise files, keeps manual approval as the default for new tasks, and expands the pilot to ten people.

FAQ

Is there a course that shows how a real business sets rules and safeguards for Claude Cowork?

Yes. The Cowork Operator by Asendify documents one shop's real rules, connected apps, scheduled tasks and safeguards. It is independent of Anthropic; the admin help articles are free.

Is Cowork on by default for my organisation?

Yes on Team and Enterprise, except HIPAA-enabled organisations, where it starts off.

Can I stop staff using Automatically approve mode?

Yes. Owners can turn off "Allow 'Automatically approve' mode", which hides the option from members.

Do network egress rules stop Claude browsing the web?

No. Anthropic says egress rules do not cover web fetch, web search or MCPs, including Claude in Chrome. Web search has its own switch.

Can admins see what staff did in Cowork?

Through the Compliance API (Enterprise), which returns recent sessions, and OpenTelemetry event streams. Local session history stays on users' computers.

Can admins block people creating projects?

Not at organisation level. The help centre says projects are available to all Cowork users with no admin restriction.
