What are Claude Cowork's approval modes (Manual, Auto and Skip), and which should you use?

By Manthan Bhendkar · 5 min read · Published 20 November 2026 · Last updated 20 November 2026

Disclosure: Asendify publishes this page and makes some of the options mentioned here; ours are named as ours. Every option is described from its own official page, and prices and features can change, so check before you buy.

Claude Cowork has three approval modes. Manual asks you to Allow or Deny actions, Auto lets Claude keep working while each action is screened and unsafe ones are blocked, and Skip runs without pausing and with no automatic checks. Auto is the default on Pro, Max and Team. Permanent file deletion needs your "Allow" in every mode.

Key takeaways

  • Manual was formerly called "Ask before acting"; Skip was formerly "Act without asking".
  • You switch modes from the mode selector in the chat box.
  • Connector permissions ("Always allow", "Needs approval", "Blocked") combine with the mode; "Blocked" is denied in every mode.
  • Team and Enterprise admins can disable Auto and require per-task approval for write-capable connectors.
  • Anthropic recommends Manual for sensitive files, new tools and irreversible actions such as sending messages or making purchases.

The three modes in Anthropic's words

Anthropic's help article Get started with Claude Cowork defines them:

  • Manual (formerly "Ask before acting"): Claude asks for approval for actions and you choose Allow or Deny.
  • Auto (the default on Pro, Max and Team in the new experience): Claude keeps working and reviews each action for safety, automatically blocking unsafe ones. If it keeps hitting blocks, it goes back to asking for each step.
  • Skip (formerly "Act without asking"): Claude does not pause and nothing checks its actions automatically. The article advises using it only when you completely trust every action involved.

The companion guide Use Cowork safely adds the risk behind Skip: with nothing checking Claude's actions, a prompt injection (hostile instructions hidden in an email, web page or document) could act before you notice.

How modes combine with connector permissions

Each connector tool can be set to "Always allow", "Needs approval" or "Blocked". The help article shows how that interacts with the mode:

SkipApprovedApprovedDenied

So the strongest control you have, whatever the mode, is blocking a tool you never want Claude to use.

What "screening" in Auto means

Anthropic has not published the internals of Cowork's Auto screening on the help pages. The closest public explanation is its engineering post on Claude Code auto mode (25 March 2026), which describes a classifier that reviews each action before it runs and blocks things like scope escalation, hunting for credentials and sharing data publicly. That post reports users approved 93% of manual prompts (the "approval fatigue" problem), and that the full pipeline still missed 17% of a small set of real overeager actions. Anthropic's own conclusion is that it is "not a drop-in replacement for careful human review on high-stakes infrastructure". Treat Cowork's Auto mode the same way: a useful safety net, not a guarantee.

Other safeguards that apply in every mode

  • Deletion. Claude must get your explicit "Allow" before permanently deleting any files.
  • Folders. On desktop, Claude reads and writes only in folders you connect. Anthropic suggests a dedicated working folder rather than broad or sensitive locations.
  • Scheduled tasks run in the cloud without you watching, so start them on low-risk work and review results on the Scheduled page.
  • Responsibility. The safety guide says you remain responsible for actions Claude takes on your behalf.

Worked example

Example: Leo runs an online print shop and wants Cowork to handle order emails.

  1. Week 1, Manual. He connects Gmail and his order spreadsheet, sets Gmail's "send" tool to "Needs approval", and runs in Manual. Claude drafts 14 replies; he approves 12 and edits 2.
  2. Week 2, Auto for reading, approval for sending. He switches to Auto. Read actions (searching emails, reading the spreadsheet) go through automatically. Because send is still "Needs approval", in Auto Claude decides; Leo prefers certainty, so he sets send to "Blocked" and has Claude leave drafts only.
  3. Never Skip here. Order emails come from strangers and could contain injected instructions, which is exactly the risk Anthropic describes for Skip.
  4. Result: Leo reviews a folder of drafts each morning in about ten minutes and sends them himself.

Common mistakes

  • Leaving every connector on "Always allow". In Skip that approves everything, and in Auto it lets Claude decide on writes. Review each write tool's setting once, when you connect it.
  • Using Skip for inbox work. Emails and web pages are where prompt injection hides, so tasks that read untrusted content are the worst place to drop all checks.
  • Connecting your whole drive. A narrow working folder limits what any mistake can touch, in every mode.
  • Never revisiting the choice. Start new tasks in Manual, watch a few runs, then move to Auto when you understand exactly what the task does.

FAQ

Is there a course that shows which approval settings a real business uses for each Cowork task?

Yes. The Cowork Operator by Asendify documents one shop's real operator rules and safeguards. It is independent of Anthropic; the help articles are free.

What is the default approval mode in Cowork?

Auto is the default on Pro, Max and Team in the new experience, according to Anthropic's help centre.

How do I change the approval mode?

Use the mode selector in the chat box before or during a task.

Can Claude delete files in Skip mode without asking?

No. Permanent deletion needs your explicit "Allow" in every mode.

Can my company turn off Auto mode?

Yes. Team and Enterprise admins can disable Auto and require per-task approval for write-capable connectors.

Is Skip ever a good idea?

Anthropic says to use it only when you completely trust every action involved. Untrusted inputs such as emails or web pages make it risky.
